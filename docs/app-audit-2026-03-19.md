## CRITICAL / HIGH Severity

### H-1. Avatar Storage Key Path Traversal
**File:** `app/api/users.py:302`
**Issue:** Validation uses `startswith(f"avatars/{user_id}/")` which allows path traversal (`avatars/{user_id}/../../victim/avatar.jpg`).
**Fix:** Use strict regex: `re.match(rf"^avatars/{re.escape(user_id)}/[a-zA-Z0-9_\-\.]+$", key)`

### H-2. Missing Transaction in Job Finalization
**File:** `app/generation/worker.py:273-327`
**Issue:** Three independent writes (create image row → commit credit → update job) have no transaction wrapper. If credit commit fails after image row is written, job is stuck and credits are inconsistent.
**Fix:** Wrap all three operations in a single Supabase RPC or reorder to commit credit last with compensation logic.

### H-3. Stripe Webhook Secret Not Validated on Missing
**File:** `app/payment/adapters/stripe_adapter.py:84`
**Issue:** `settings.STRIPE_WEBHOOK_SECRET` used without null/empty check. If env var is missing, signature verification may accept any payload.
**Fix:** Validate `STRIPE_WEBHOOK_SECRET` is non-empty in `__init__` or at startup; raise `RuntimeError` if empty in production.

### H-4. Concurrent Generation Counter Race Condition
**File:** `app/entitlement/service.py:196-198`, `app/generation/worker.py:362-365`
**Issue:** `max_concurrent_generations` check reads Redis without locking, then increments separately. Two simultaneous requests can both pass the check.
**Fix:** Use atomic Lua script or `WATCH/MULTI` to check-and-increment in one operation.

### H-5. Credit Reserve Double-Spend (Documented)
**File:** `app/migrations/0014_credit_ledger_rpcs.sql:36-39`
**Issue:** `credit_reserve()` RPC has an acknowledged TOCTOU race — two concurrent reserves can both read balance=1 and succeed.
**Fix:** Add `pg_advisory_xact_lock(hashtext(p_user_id::text))` as documented in the migration comment. Monitor for ledger imbalances.

### H-6. API Keys Default to Empty String — No Startup Validation
**File:** `app/config.py:22-28`
**Issue:** `FAL_API_KEY`, `AWS_ACCESS_KEY_ID`, `STRIPE_API_KEY`, `ANTHROPIC_API_KEY` all default to `""`. App starts in production without these, silently degrading.
**Fix:** Remove defaults for required production keys (pydantic-settings raises on missing) or add explicit startup validation in `main.py` lifespan.

## MEDIUM Severity

### M-1. Rate Limiting Ineffective Behind Load Balancer
**File:** `app/api/auth.py:108-119`
**Issue:** `request.client.host` returns the LB/proxy IP (not real client) when behind ALB/nginx. Per-IP rate limiting becomes per-LB limiting.
**Fix:** Configure trusted proxy middleware; use `X-Forwarded-For` only from verified upstream.

### M-2. Social Login Username Collision Race
**File:** `app/api/auth.py:440-444`
**Issue:** Between `check_username_taken` and the actual upsert, another concurrent login can claim the same auto-generated username.
**Fix:** Rely on DB UNIQUE constraint + retry loop with new suffix on conflict.

### M-3. Username Max Length Exceeded After UUID Suffix
**File:** `app/api/auth.py:444`
**Issue:** 30-char username + `_` + 6-hex = 37 chars, exceeding `max_length=30`.
**Fix:** Truncate base username before appending suffix: `auto_username = auto_username[:30 - len(suffix)] + suffix`

### M-4. Credit Reservation Double-Release Risk
**File:** `app/generation/worker.py:298-307`, `worker.py:407-435`
**Issue:** `_fail_job()` calls `ledger.release()` without checking if credit was already committed. Double-release could cause negative balances.
**Fix:** Check job status (committed vs reserved) before attempting release.

### M-5. Post Creation Job Status TOCTOU
**File:** `app/api/posts.py:100-115`
**Issue:** Job status checked at read time; between check and post INSERT, job could be marked failed by a concurrent process.
**Fix:** Use atomic SQL: `INSERT INTO posts ... WHERE job.status = 'completed'`.

### M-6. Tier Cache JSON Parse Unhandled
**File:** `app/entitlement/tier_repo.py:83`
**Issue:** `json.loads(cached)` without try-catch. Corrupted Redis cache crashes tier lookups.
**Fix:** Wrap in try-except, delete corrupted cache key, fall through to DB.

### M-7. Tier Record NULL Fields Not Validated
**File:** `app/entitlement/tier_repo.py:32-42`
**Issue:** `float(row["identity_similarity_threshold"])` crashes if field is NULL.
**Fix:** Add explicit None checks or provide defaults before type conversion.

### M-8. Concurrent Key TTL Expires Mid-Job
**File:** `app/generation/worker.py:365, 404`
**Issue:** TTL set to `GENERATION_TIMEOUT_SECONDS + 60`. If job takes longer, key expires and DECR at cleanup fails silently, leaving counter dirty.
**Fix:** Extend TTL periodically during long-running jobs, or validate key existence before DECR.

### M-9. Cost Tracker Circuit Breaker Race
**File:** `app/generation/cost_tracker.py:225-239`
**Issue:** Two threads can read stale `_CB_OPEN_AT_KEY` value and disagree on state transition timing.
**Fix:** Use atomic Lua script or Redis compare-and-swap.

### M-10. Storage Upload Not Rolled Back on DB Failure
**File:** `app/image_pipeline/pipeline.py:143-174`
**Issue:** File uploaded to storage (line 152), then DB row created (line 156). If DB write fails, cleanup is attempted but not verified.
**Fix:** Verify cleanup success; add periodic orphan-file sweep job.

### M-11. Rate Limiter DECR Creates Counter Imbalance
**File:** `app/advisor/content_filter.py:86`
**Issue:** DECR after rate limit exceeded gives the next request a free attempt.
**Fix:** Don't decrement; let the count decay naturally with TTL.

### M-12. Soft-Delete on Users Not Atomic
**File:** `app/repositories/user_repo.py:118-132`
**Issue:** `deleted_at` + `username_reserved_until` updated without transaction. Crash between leaves user half-deleted.
**Fix:** Wrap in single RPC or ensure both fields are in one UPDATE statement.

### M-13. Balance Doesn't Account for Pending Reserves
**File:** `app/entitlement/ledger.py:33-50`, `app/entitlement/service.py:103`
**Issue:** `balance()` sums committed deltas only. Users see available balance but next generation may fail because pending reserves already deducted.
**Fix:** Document as eventual-consistent or return `{available, pending}` tuple.

### M-14. Quarantine Record Write Failure Silenced
**File:** `app/image_pipeline/pipeline.py:109-117`
**Issue:** If quarantine row write fails, no exception raised — image passes through unrecorded.
**Fix:** Raise exception on quarantine write failure; fail closed.

### M-15. Webhook Event Deduplication Race
**File:** `app/repositories/subscription_repo.py:73-82`
**Issue:** Concurrent duplicate webhooks can both pass the existence check.
**Fix:** Use `INSERT ... ON CONFLICT DO NOTHING` on unique `event_id` column.

### M-16. Image Validators Can Crash Unhandled
**File:** `app/image_pipeline/pipeline.py:97-101`
**Issue:** Validator exceptions propagate as 500 instead of 422.
**Fix:** Wrap validators in try-catch; map to `HTTPException(422, ...)`.

### M-17. Prompt Template Files Not Validated at Startup
**File:** `app/generation/prompt_builder.py:184-190`
**Issue:** Template files read at runtime. If missing, worker crashes on first generation.
**Fix:** Validate templates exist during module load or app startup.

### M-18. Missing `.dockerignore`
**File:** Project root
**Issue:** Docker build context includes `.git`, `__pycache__`, `.env`, etc. Bloats image and risks secret inclusion.
**Fix:** Create `.dockerignore` with standard exclusions.

### M-19. `--proxy-headers` Without Trusted Proxy Config
**File:** `Dockerfile:40-42`
**Issue:** `--proxy-headers` trusts `X-Forwarded-For` from any source. Without reverse proxy, attacker can spoof IP.
**Fix:** Document trusted proxy assumption; consider removing flag or adding `TrustedHostMiddleware`.

### M-20. Identity Checker Startup Failure Silent
**File:** `app/generation/identity_checker.py:27-57`
**Issue:** If `preload_arcface()` fails at startup, `_arcface_app` stays None. Worker crashes at first identity check instead of failing fast.
**Fix:** Raise at startup if preload fails (fail fast).

### M-21. Disposable Email Blocklist Silent Fallback
**File:** `app/services/disposable_email.py:18-24`
**Issue:** If blocklist package broken (< 100 domains), silently falls back to 9-domain hardcoded list. 90% of disposable emails bypass.
**Fix:** Raise `RuntimeError` if blocklist < 100 to fail fast.

### M-22. Subscription Update Silent No-Op
**File:** `app/repositories/subscription_repo.py:59-67`
**Issue:** Update by `provider_subscription_id` doesn't verify row exists. Wrong ID = silent success with 0 rows updated.
**Fix:** Return row count; raise if 0 rows affected.
